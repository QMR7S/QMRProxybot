## Release-blocking issues

1. **No persistent host provisioned**. Termux plus Cloudflare Quick Tunnel is vulnerable to Android process termination and temporary hostname changes. A named tunnel alone does not remove the phone dependency.
2. **Incomplete deployable artifact**. The reference excludes live data feeds (`nodes.json`, `extra-proxies.json`), generated quality/health reports, runtime launcher scripts, `SQLite`, credentials, and operating-system supervision. Never put sensitive user data or credentials in this public branch.
3. **Platform and domain coupling**. Paths, `tmux` conventions, current webhook identity validation, and temporary-domain assumptions require implementation and tests before moving to Linux or another hostname.
4. **Two-runtime reconciliation missing**. The repository's existing native Telegram Serverless code and this Termux snapshot are different implementations. Do not merge reference code blindly into main, start two webhook consumers, or claim a production deployment from this PR.
5. **Security and authorization test matrix missing**. Exercise Telegram-signed Mini App authorization, owner-only Ops/Admin, queued Telegram update handling, retry semantics, and backups with synthetic credentials and data in an isolated host.
6. **Migration and rollback need an approved cutover plan** preserving all pending updates, never overwriting a newer live DB with an older snapshot, and ensuring exactly one active consumer.
