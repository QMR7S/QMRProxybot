# Controlled notifications — review gate
Based on live V14.1, original TGCloud application. Three additive tables only. No migration of old V6 campaigns if any exist; the deployment script stops on such records. No legacy cursor dispatcher. No public-site changes.
Users explicitly opt in via /notifications on (channel membership checked at opt-in) and may opt out at any time, including blocked users. Opt-out and block status are checked at claim; already-started Bot API calls cannot be recalled. Deleting data removes opt-in and settled delivery rows; if an attempt is active it reports that deletion is incomplete and asks for a later retry. Historical owner-authored announcement text is not user chat history.
Owner only, private chat: /broadcast_test TEXT creates a one-recipient draft. /broadcast TEXT creates a snapshot of eligible opt-in users only after a successful canary. Draft creation and confirmation never send. Each explicit next-recipient press is fenced by a monotonically increasing sequence. Atomic SQL claim allows one in-flight delivery across campaigns. Unknown outcomes halt the campaign; no retry or exactly-once claim. 429 cooldown blocks subsequent claims while its journal row remains. Cancellation does not undo delivery. Manual /broadcast_abandon ID CONFIRM after five minutes marks an orphaned attempt unknown and cancels, never repeats it. Campaigns with >1000 recipients stop rather than truncate silently.
Deployment: bash tools/deploy_notifications_v13.sh "$HOME/QMRCloud_V14.07AVpc"
Requires the exact clean V14.1 release, preserves all static files, private snapshot of the four original tables, verifies migration preview, live native SQL no-row probe, then targeted module push. No new bot, token change, webhook mutation or automatic sends. If schema stage is applied but later gate fails, retain release and report stage; do not rerun blindly.
Independent MTProto TCP handshake monitoring is not implemented here. Existing source feed is retained and quality remains unknown without valid measurements. Real Admin action audit and real non-owner UI rejection still require live tests.
